# How the UI rules are applied in PaidLoop

The rules come from the owner's own file `FRONTEND-UI-UX-RULES.md`, which is not copied into this repo because it comes from another project. This page lists every section of that file with what PaidLoop does. **Applied** means done as written. **Adapted** means the idea is kept and the details changed, with the reason. **Skipped** means not done, with the reason.

Checks that run by themselves: `npm run check:ui` (also runs in `npm run build`) and `npm run walk` (needs the app running).

| Section | Status | What PaidLoop does |
|---|---|---|
| **0. Project card** | Applied | Product: PaidLoop. Category: small internal business tool with a dashboard. User: a small business owner, a few minutes a day, laptop or phone. Slowest device: a laptop with 2 GB graphics. Density: balanced. Brand colour: Primary blue. One typeface. Light and dark. Languages: English and German, no right-to-left. |
| **1. Principles** | Applied | Data first, one look, fast by default, accessible as the floor, mobile first, say what to do next ("Next steps", errors with a fix, empty states with an action). |
| **2. Architecture** | Adapted | The rules assume Next.js, Tailwind and a monorepo. PaidLoop uses React, Vite and plain CSS. Kept: tokens in one file (`tokens.css`), shared components in one file, pages only compose them, framework-free helpers in `api.ts`. Skipped: tiers with import lint, a design-system package, a route manifest, server components and the React Compiler, because the app is small. |
| **3. The look** | Applied | White cards with a 1px hairline on a tinted canvas, no shadow on cards. Shadows only on things that float (menus, dialogs, the save bar, toasts). No glass, no `backdrop-filter`, no decoration. Radius 6, pills 4, alerts 8, dialogs 12. The scrollbar is thin and quiet. The search clear button is hidden. One primary colour. |
| **4. Colour** | Applied | Primary and neutral 50 to 900, and success, warning and error at 100, 500 and 700, exactly as in the rules. (The rules say 23 colours, but their own list adds up to 29 plus white. The check expects 29.) Screens name roles such as `--surface` and `--text-muted`, never a shade. Status colours always come with a word or icon. **Contrast:** 60 pairs in both themes are checked from the real stylesheet. The check found two real errors on the first run and the browser walk found one more (the logo in dark mode). **Dark:** the same colours with roles swapped. **Not done:** brand presets for tenants (PaidLoop has one owner), and a lint for palette classes (there is no Tailwind). `check:ui` refuses hex and rgb values outside `tokens.css`. |
| **5. Typography** | Adapted | The scale is exactly as in the rules. Numbers use `tabular-nums`. Labels are medium weight. Density never changes a font size. **Adapted:** the font is the system font, not a self-hosted one, because nothing may be requested from another site and no font file was available without a download. The rules also say hero figures are 30px, so the big numbers shrank from the earlier 48px design. |
| **6. Spacing and size** | Applied | Named steps (`--space-hair` to `--space-page`) in two densities. `check:ui` fails on a pixel value in padding, margin or gap. Every grid has a one-column base for phones. Density switch (Comfortable or Compact) is in the Appearance menu, saved on this computer, and applied before the first paint. Skipped: `FieldGrid` as a component (forms use one shared grid class), and saving density on a server (there is no user account). |
| **7. Layers** | Applied | Five tokens, nothing above a toast. A literal `z-index` fails the check. |
| **8. Motion** | Applied | Speeds and two curves come from tokens. Animations are opacity and transform only (checked). Enter and exit are the same everywhere: toast from the bottom right, dialog fades and rises 8px, menus fade and zoom from 95%. No bounce, no hover lift, no `transition-all`, nothing animates in forms, lists or sorting. Reduced motion: everything runs once in 1ms and the spinner rests. Not applicable: the changed-row highlight, because the lists are not live (they are read when opened). |
| **9. Loading** | Applied | Waiting for data shows the page title and a skeleton in the final shape (list, detail, form, dashboard, cards). It holds its room at once and is drawn only after 250ms, so a fast answer shows nothing. A screen reader hears "Loading" straight away. A re-read keeps the content, dims it and draws a thin line on the top edge. Buttons are busy at once with a spinner, `aria-busy` and a word like "Saving...". The skeleton shows only when there is no data yet. Skipped: dimming the page on link press, because navigation is instant, and determinate progress, because PaidLoop has no exports or uploads with a known size. |
| **10. Page templates** | Adapted | Every page has the same header: one `<h1>`, actions on its row, a back link above when under another page, and help behind an (i) button. List (Invoices, Audit), detail (Invoice), wizard (New invoice), settings, dashboard (Home), and a narrow customer page. **Adapted:** the dashboard keeps two panels side by side from 768px, because dashboards are the exception to one column. The settings page saves as one form with one save bar, instead of each card saving itself. Tables become ruled cards below 768px, never a sideways scroll. The list has no refresh button, but its data is only read when opened, so it keeps a visible re-read. Skipped: right-click row menus (hard to find for a casual user), and focus mode. |
| **11. Navigation and shell** | Adapted | A sticky top bar with a hairline holds the menu, status lights, language, appearance and help. There is no sidebar, pinned screens or command palette, because there are only six screens. Exactly one link is current (`aria-current`). Skipped: permissions, tenants. |
| **12. Components** | Adapted | Built once: Field, StatusPill, Spinner, BusyLabel, Loading, PageHeader, InfoButton, TwoStepButton (the only confirm), Empty, ErrorBox, Toast, LangSwitch, AppearanceMenu, BarRows. Pills always carry text. Toasts appear bottom right only. Icons are plain text marks, because an icon sprite is not worth it for a few marks. |
| **13. Data and live UX** | Adapted | Not a realtime app: the browser asks the server, and the server asks PayPal every 20 seconds. **Applied:** server search is prefix search with an index range (checked by a test with `EXPLAIN QUERY PLAN`), and the audit list uses cursor paging. **Adapted:** the invoice list uses page numbers, because it can be sorted by any column and shows totals. That is safe because the list is not live. A rows-inserted-between-pages problem can only happen if a new invoice is made while someone is on page 2. **Trade-off:** typing "0003" does not find RE-2026-0003 any more. The search box says to start with the number. |
| **14. Responsive** | Applied | Mobile first. **Verified at 320, 375, 768, 1024 and 1440** by the browser walk, with no sideways scroll and no content past the right edge. Controls are at least 40px high on a phone. |
| **15. Accessibility** | Applied | **axe** runs on every screen at every width in both themes, German, compact and reduced motion, with WCAG 2.0 and 2.1 level A and AA rules. Skip link, visible focus ring, labels tied to fields, errors tied to fields by `aria-describedby`, one `<h1>` per page (checked), colour never alone, dialogs from the native `<dialog>` element (focus is trapped and restored). Skipped: `eslint-plugin-jsx-a11y` (no ESLint set up). **Not tested:** a real screen reader. |
| **16. Keyboard** | Adapted | Not a data-entry product, so no Tally-style keys. Kept: N, I, A, H go to a screen, `/` jumps to search, `?` lists shortcuts, Ctrl+Enter does the main action, Escape closes menus and dialogs. Letter keys do nothing while typing in a field. |
| **17. Brand and logo** | Skipped | PaidLoop has a typed name only, no logo file. |
| **18. Performance** | Adapted | The whole app is one 252 KB script (80 KB compressed) and a 31 KB stylesheet. There is no per-route budget or lazy loading, because it is small. No `backdrop-filter`, and only loaders animate on repeat. No service worker. |
| **19. Print** | Applied | The invoice is a PDF in the customer's language with a single colour. Printing hides the menu and the buttons. |
| **20. Content and microcopy** | Adapted | Sentence case, one money and date format per language, errors say what happened and the fix, empty states carry an action. **Adapted:** error text is chosen by the server in the requested language, not from a code map in the browser. |
| **21. Don'ts** | Applied | Each one is either a check in `check:ui` (colours, literal durations, `transition-all`, `backdrop-filter`, sideways-scroll tables, literal `z-index`, spacing pixels, browser dialogs) or true by construction. |
| **22. Enforcement** | Adapted | Colour tokens, spacing, motion, contrast, one `<h1>`, both languages complete: `npm run check:ui`. Overflow, axe, console errors, touch size, theme and language: `npm run walk`. Skipped: tier lint, route manifest test, bundle ceiling, sprite test (nothing to test). |
| **23. Testing the UI** | Adapted | The walk uses the browser directly over its debugging port, so there is no Playwright install. It visits 11 screens in 5 variants, 143 checks in all. Not done: a signed-in walk as two roles (there is one role). |
| **24. Category** | Applied | Treated as an internal tool plus an analytics dashboard: tokens, templates, accessibility and the loading rules kept, presets and command palette skipped. |
| **25. Starter prompt** | Not needed | The app already existed. |
| **26. Definition of done** | Applied | Every item is checked by `check:ui` or `walk`, except "looks considered", which is a judgement, and "reduced motion on: still usable", which the walk checks only for errors and layout. |
| **27. Process** | Applied | Decisions are written here and in `docs/USABILITY.md`. Earlier screens were changed on the owner's request. |

## What a new screen must do

1. Use `PageHeader`, and `Loading` with a shape while data is missing.
2. Use roles and spacing steps from `tokens.css`. Do not write a colour, a pixel gap or a duration.
3. Tables get `className="rtable"` and `data-label` on every cell, so they become cards on a phone.
4. Every text goes into both languages in `i18n.tsx`.
5. Run `npm run build` and `npm run walk`. Both must pass.
